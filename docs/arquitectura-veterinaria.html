Guía de arquitectura y dominio

TP Veterinaria

Red de clínicas veterinarias y derivación de muestras a laboratorio central

Resumen

Aplicación web para administrar clientes, pacientes, atención veterinaria y derivación de muestras biológicas. El frontend es una SPA en React; el backend expone una API REST con FastAPI, y la persistencia activa se realiza en SQLite. El dominio pone especial énfasis en seguir cada muestra desde su extracción hasta el resultado o rechazo.

Qué aporta cada tecnología y por qué encaja

Python 3.12

Por qué: lenguaje claro y productivo para implementar reglas de negocio y una API; además es el lenguaje principal del backend definido para el trabajo. Dónde: lógica, servicios, dominio, acceso a datos y pruebas en backend/app/.

FastAPI + Uvicorn

Por qué: FastAPI facilita exponer endpoints REST, validar entradas tipadas y obtener documentación OpenAPI/Swagger; Uvicorn ejecuta la aplicación ASGI durante desarrollo y ejecución. Dónde: creación de la app y registro de routers en backend/app/main.py; ejecución con uvicorn app.main:app.

Pydantic 2

Por qué: ofrece validación y conversión de datos de entrada/salida basada en modelos, ayudando a definir contratos claros para los endpoints. Dónde: esquemas de request/response organizados en backend/app/esquemas/.

React 19

Por qué: permite construir una interfaz interactiva a partir de componentes reutilizables, adecuada para pantallas de gestión con formularios, tablas y estados. Dónde: páginas y componentes en frontend/src/.

Vite 8

Por qué: brinda servidor de desarrollo rápido con recarga y un proceso de build para producción integrado con React. Dónde: scripts npm y configuración del frontend en frontend/vite.config.js.

React Router DOM

Por qué: permite navegar entre módulos como mascotas, turnos, laboratorio y reportes sin recargar la página completa. Dónde: definición de rutas en frontend/src/App.jsx.

Axios

Por qué: centraliza llamadas HTTP, cabeceras de autenticación y tratamiento común de respuestas/errores. Dónde: instancia e interceptores en frontend/src/api/axiosConfig.js, consumidos por módulos de API.

React Hook Form

Por qué: simplifica el manejo del estado y validación de formularios con menos lógica manual. Dónde: formularios de alta/edición en las páginas que lo importan.

Tailwind CSS + CSS

Por qué: Tailwind facilita componer estilos desde utilidades; CSS propio deja personalizar diseños o estilos globales. Dónde: frontend, integrado mediante PostCSS y hojas de estilos.

SQLite + sqlite3

Por qué: una base relacional local, sin servidor separado, resulta sencilla de instalar y apropiada para un TP o una aplicación de alcance acotado. Las relaciones y restricciones modelan datos conectados. Dónde: schema.sql, conexion.py y los DAOs de persistencia/.

JWT + bcrypt

Por qué: JWT permite transportar identidad y rol entre solicitudes sin mantener una sesión de servidor tradicional; bcrypt almacena hashes de contraseñas en vez de contraseñas legibles. Dónde: core/seguridad.py y dependencias de autenticación/autorización.

pytest + GitHub Actions

Por qué: pytest automatiza verificaciones del backend; Actions ejecuta pruebas y build ante cambios para detectar regresiones temprano. Dónde: pruebas en backend/tests/ y workflow .github/workflows/ci.yml.

Nota de precisión: SQLAlchemy aparece en requirements.txt, pero el flujo de persistencia revisado usa SQL directo con sqlite3 y DAOs. Por eso no se presenta como ORM actualmente aplicado.

Decisiones arquitectónicas

Cliente-servidor, con frontend SPA y API REST

El navegador presenta la aplicación y FastAPI entrega datos y operaciones por HTTP. Mantener interfaz y backend separados permite que cada capa evolucione con responsabilidades y herramientas propias.

Backend dividido por responsabilidades

rutas/ recibe solicitudes; servicios/ coordina casos de uso; persistencia/ gestiona SQL y DAOs; dominio/ representa entidades y reglas. Esto evita concentrar toda la lógica en los endpoints.

Esquema SQL explícito y constraints

schema.sql define entidades relacionales, claves foráneas, checks, unicidad e índices. Las reglas importantes quedan protegidas también en la base de datos, no solo en la interfaz.

Autorización por roles

Los roles de administrador, veterinario, laboratorio y cliente permiten aplicar permisos adecuados a cada tipo de usuario a través de dependencias de FastAPI.

Patrón Singleton: por qué y dónde

Ubicación: backend/app/persistencia/conexion.py, clase DatabaseSingleton. Intención: disponer de una única instancia de conexión SQLite compartida por los DAOs en el proceso de la aplicación.

¿Por qué usarlo aquí?

SQLite trabaja con un archivo local. Centralizar la conexión simplifica que los DAOs usen la misma base y evita que cada DAO cree su propia conexión. El lock de clase alrededor de __new__ protege la creación de la instancia frente a inicializaciones simultáneas.

¿Cómo está aplicado?

DatabaseSingleton.__new__ crea y guarda cls._instancia una sola vez; get_conexion() devuelve la conexión compartida. La conexión habilita check_same_thread=False y las claves foráneas. BaseDAO obtiene esa instancia para ejecutar sus operaciones.

Alcance y cuidado: este singleton es por proceso, no una garantía de una única conexión entre varios procesos o servidores. Una conexión compartida puede limitar concurrencia; si la app crece, conviene evaluar conexiones por solicitud o un pool y revisar cuidadosamente el acceso concurrente.

Patrón State: por qué y dónde

Ubicación: estados concretos en backend/app/dominio/estados.py y entidad MuestraBiologica en backend/app/dominio/modelos.py. La muestra delega acciones —empaquetar, despachar, recibir y analizar— en su objeto de estado actual.

¿Por qué usarlo?

El comportamiento válido cambia durante la vida de una muestra. Con State, las reglas de cada etapa se reúnen en clases distintas, en vez de crecer en una cadena de condicionales por todos los métodos. Esto hace explícitas las transiciones y permite rechazar operaciones fuera de orden.

¿Cómo funciona en este proyecto?

MuestraBiologica mantiene self.estado. Los estados EstadoExtraida, EstadoEmpaquetada, EstadoEnTransito y EstadoRecibida implementan acciones permitidas; la clase base rechaza por defecto las demás con ExcepcionTransicionEstado. Cada transición llama a muestra.cambiar_estado(...), que agrega un evento al historial en memoria de ese objeto.

Extraída → Empaquetada → En tránsito → Recibida → Analizada
Si el precinto está roto: En tránsito → Rechazada durante la recepción

Los estados analizada y rechazada son finales para el modelo de dominio: no definen nuevas transiciones. La decisión del precinto se maneja en EstadoEnTransito.recibir().

Distinción importante: además del modelo State de dominio, el servicio ServicioMuestras y MuestraDAO.cambiar_estado() persisten cambios e historial en SQLite. Son piezas conectadas del flujo, pero no hay que confundir la instancia de dominio y su patrón State con la lógica de persistencia del servicio.

Entidades relevantes del dominio

Cliente

Persona responsable de mascotas y destinataria de comprobantes; puede vincularse con un usuario.

Mascota

Paciente con especie, raza, sexo y datos de nacimiento; tiene un cliente responsable.

HistoriaClinica

Registro clínico de una mascota que agrupa consultas.

Clinica

Sede de atención con veterinarios, consultas y turnos asociados.

Veterinario

Profesional que atiende consultas y puede tener turnos en una clínica.

Turno

Reserva para una mascota; contempla fecha, horario, estado y veterinario asignado.

Consulta

Atención clínica vinculada a historia, veterinario y clínica; registra motivo, diagnóstico y tratamiento.

Vacuna / EsquemaVacunal

Catálogo de vacunas y reglas por especie, edad, obligatoriedad e intervalo de refuerzo.

VacunaAplicada

Aplicación registrada durante una consulta, con fecha y lote.

Laboratorio

Destino de las órdenes de derivación y receptor de muestras.

TipoAnalisis

Catálogo de estudios, tipo de muestra, precio y temperatura de almacenamiento.

OrdenDerivacion

Pedido de estudio asociado a una consulta, un análisis y un laboratorio.

Muestra

Material biológico con código, tipo, fecha de extracción y estado; es central para la trazabilidad.

HistorialEstadoMuestra

Bitácora de estados, fechas, usuarios y observaciones de una muestra; la base prohíbe actualizarla o borrarla.

RemitoBiologico

Documento de envío desde una clínica hacia un laboratorio, con estado y fecha.

Contenedor y Precinto

El contenedor conserva muestras; el precinto permite comprobar la integridad del envío.

EventoEnvio / RecepcionLab

Registran hitos del transporte y recepción, incluida la verificación del precinto.

ResultadoAnalisis

Resultado generado por el laboratorio y asociado a una muestra.

Comprobante / ItemComprobante

Comprobante de atención con renglones de consulta, vacuna o análisis.

Usuario

Cuenta autenticable con rol; puede relacionarse con un cliente o veterinario.

Relaciones y flujo del negocio

Cliente → Mascota → Historia clínica → Consulta → Orden de derivación → Muestra → Remito y transporte → Recepción de laboratorio → Resultado

Una mascota tiene responsable e historia clínica; la historia reúne consultas; una consulta puede originar órdenes. El remito conecta la clínica, el laboratorio, el contenedor y el precinto. La muestra mantiene su propio ciclo de vida y registro de trazabilidad.

Observaciones técnicas

  • La conexión define una ruta SQLite fija; también existe una configuración separada con RUTA_BD. Conviene unificar ambas fuentes de configuración.
  • En main.py se observan duplicados del registro CORS y del middleware de renovación de token; conviene consolidarlos.
  • La prueba visible en el repositorio comprueba el endpoint de salud. La CI corre pytest y construye el frontend.
  • Las razones de selección explicadas en este documento son la justificación arquitectónica de las tecnologías y patrones observados en el código; no implican que exista un ADR formal o una decisión histórica documentada para cada elección.

Conclusión

La solución combina gestión clínica con logística de laboratorio. React, FastAPI y SQLite ofrecen una estructura directa para separar interfaz, API y persistencia. En el dominio, Singleton concentra la conexión de base de datos, mientras State expresa las transiciones permitidas de una muestra. La trazabilidad conecta esas transiciones con la auditoría operacional.
