Guía de arquitectura y dominio

TP Veterinaria

Red de clínicas veterinarias y derivación de muestras a laboratorio central

Resumen

Aplicación web para administrar clientes, pacientes, atención veterinaria y derivación de muestras biológicas. El frontend es una SPA en React; el backend expone una API REST con FastAPI, y la persistencia activa se realiza en SQLite. El dominio pone especial énfasis en el seguimiento de muestras desde su extracción hasta el resultado o rechazo.

Frameworks y tecnologías

Frontend

  • React 19 y Vite 8.
  • React Router DOM para navegación cliente.
  • Axios para llamadas HTTP a la API.
  • React Hook Form para manejo de formularios.
  • Tailwind CSS 4 y hojas CSS propias.

Backend y datos

  • Python 3.12, FastAPI y Uvicorn.
  • Pydantic 2 para esquemas y validación de datos.
  • SQLite, acceso mediante sqlite3 y consultas SQL directas.
  • JWT para autenticación, bcrypt para hashes de contraseña.
  • pytest para pruebas; GitHub Actions para CI.

Aclaración: SQLAlchemy figura en las dependencias, pero el código de persistencia revisado utiliza sqlite3 y DAOs, no SQLAlchemy como ORM activo.

Decisiones arquitectónicas

Aplicación cliente-servidor

El navegador ejecuta React y consume una API REST FastAPI. Es una aplicación organizada en dos capas desplegables, no una arquitectura de microservicios.

Backend por responsabilidades

rutas/ expone endpoints; servicios/ coordina casos de uso; persistencia/ contiene DAOs y SQL; dominio/ representa entidades y reglas.

DAO y SQLite

Los DAO encapsulan consultas y operaciones. Un singleton mantiene la conexión; schema.sql crea tablas, restricciones, índices y datos semilla al iniciar.

Patrón State

El comportamiento de MuestraBiologica depende de su estado. Cada estado habilita transiciones específicas y rechaza operaciones no permitidas.

Auditoría de trazabilidad

Los cambios de estado de las muestras se agregan a un historial. Triggers en SQLite bloquean la actualización y eliminación de esos registros históricos.

Autenticación y autorización

Tokens JWT firmados con HS256, contraseñas protegidas con bcrypt y dependencias de FastAPI para validar identidad y roles.

Frontend por rutas y páginas

App.jsx define rutas; las páginas agrupan áreas funcionales y src/api/ centraliza el cliente Axios. Hay un componente ProtectedRoute, aunque las rutas principales visibles no lo envuelven allí.

Validaciones en varias capas

Pydantic valida entradas HTTP y SQLite aplica claves foráneas, campos únicos, restricciones CHECK e índices.

Entidades relevantes del dominio

Cliente

Persona responsable de mascotas y destinataria de comprobantes; puede vincularse con un usuario.

Mascota

Paciente con especie, raza, sexo y datos de nacimiento; tiene un cliente responsable.

HistoriaClinica

Registro clínico asociado a una mascota que agrupa consultas.

Clinica

Sede de atención con veterinarios, consultas y turnos asociados.

Veterinario

Profesional de una clínica que atiende consultas y puede tener turnos.

Turno

Reserva para una mascota; contempla fecha, horario, estado y veterinario asignado.

Consulta

Atención clínica vinculada a historia, veterinario y clínica; registra motivo, diagnóstico y tratamiento.

Vacuna / EsquemaVacunal

Catálogo de vacunas y reglas por especie, edad, obligatoriedad e intervalo de refuerzo.

VacunaAplicada

Aplicación registrada durante una consulta, con fecha y lote.

Laboratorio

Destino de las órdenes de derivación y receptor de muestras.

TipoAnalisis

Catálogo de análisis, tipo de muestra, precio y temperatura de almacenamiento.

OrdenDerivacion

Pedido de estudio asociado a una consulta, un análisis y un laboratorio.

Muestra

Material biológico con código, tipo, fecha de extracción y estado actual; eje del flujo de trazabilidad.

HistorialEstadoMuestra

Bitácora append-only de estados, fechas, usuarios y observaciones de una muestra.

RemitoBiologico

Documento de envío desde una clínica hacia un laboratorio, con estado y fecha.

Contenedor y Precinto

El contenedor conserva las muestras; el precinto permite comprobar la integridad del envío.

EventoEnvio / RecepcionLab

Registran hitos del transporte y la recepción, incluida la verificación del precinto.

ResultadoAnalisis

Resultado validado por el laboratorio y asociado a una muestra.

Comprobante / ItemComprobante

Comprobante de atención con renglones de consulta, vacuna o análisis.

Usuario

Cuenta autenticable asociada opcionalmente a cliente o veterinario y con rol de acceso.

Relaciones y flujo de negocio

Cliente → Mascota → Historia clínica → Consulta → Orden de derivación → Muestra → Remito y transporte → Recepción de laboratorio → Resultado

Una mascota tiene responsable e historia clínica; la historia reúne consultas; una consulta puede originar órdenes. La muestra mantiene un historial de estados. El remito conecta la clínica de origen, el laboratorio de destino, el contenedor y el precinto. Si el precinto llega roto, la muestra debe rechazarse.

Ciclo de vida de una muestra

Extraída → Empaquetada → En tránsito → Recibida → Analizada
Si el precinto está roto: Recibida → Rechazada

Observaciones técnicas

  • La conexión define una ruta SQLite fija; también existe una configuración separada con RUTA_BD. Conviene unificar ambas fuentes de configuración.
  • En main.py se observan duplicados del middleware de renovación de token y del registro CORS; sería bueno consolidarlos.
  • La prueba visible en el repositorio comprueba el endpoint de salud. La CI corre pytest y construye el frontend.
  • El uso de una conexión SQLite singleton es simple para el alcance actual; concurrencia y crecimiento de carga merecen evaluación si el sistema evoluciona.

Conclusión

La solución combina gestión clínica con logística de laboratorio. Su decisión de diseño más distintiva es tratar la muestra como una entidad con ciclo de vida y auditoría persistente, conectando las operaciones clínicas con el transporte, la recepción segura y el resultado del análisis.
